# 交互方案：回归执行「执行 + 结果」一体化 UI 重构

> 目标：把当前分散在 **AgentRun 独立页** + **飞书回归(运行/执行历史/Trace时间轴/Baseline)** + **运行状态** 的执行相关界面，收敛成**一个连贯的「回归执行」主视图**——选用例→启动→实时看→回放/历史，是同一条流、同一套组件。

---

## 1. 现状问题（对照你给的 4 张图）

| 图 | 界面 | 问题 |
|---|---|---|
| 图1 | AgentRun 实时页（我新加的 `/agent/run`） | ① 独立路由，**没有左侧主导航外壳**，像另一个 app；② **CopilotWidget 浮层（"Ask AI"、"Executed: Go to…"紫色气泡）盖在内容上**，观感破碎；③ 与飞书回归的 Trace 时间轴**重复** |
| 图2 | 运行状态 / 运行概览 | 设备/服务健康，和"执行用例"无直接关联，但和执行入口分处两地 |
| 图3 | 飞书回归 → 执行历史（run 详情抽屉） | run 摘要 + Cases 表 + "看 Trace" 按钮——**看 Trace 又要跳到另一个 tab** |
| 图4 | 飞书回归 → Trace 时间轴 | 左 Trace列表 + 右步骤时间线（launch_app/tap_element/human_confirm…）——**这套时间线和图1 AgentRun 几乎一模一样，两套并存** |

**根因**：执行的「触发 / 实时 / 历史 / Trace / Baseline」被拆成 4 个 tab + 1 个独立页，且**实时时间线（AgentRun）与历史时间线（Trace）是两套代码两套入口**，用户在多个地方看同一件事。

---

## 2. 设计原则

1. **一条主线**：选设备+用例 → 启动 → 实时执行 → 结束即结果/Trace，**全程不跳页**。
2. **实时=回放同一个组件**：一个 `ExecutionTimeline` 组件，数据源二选一（实时 WS `agent_step` / 历史 `/agent/steps` 或 trace），UI 完全一致。彻底消灭"AgentRun vs Trace时间轴"两套。
3. **run 为中心**：一切围绕"一次 run（一条用例的一次执行）"组织：它的目标、步骤时间线、设备/模型/通道、结果。
4. **在主导航里有明确位置**：不再是浮空的独立页；套用现有 Settings 外壳（左侧主导航）。
5. **收起无关**：CopilotWidget 在执行视图里隐藏（不浮层遮挡）。

---

## 3. 统一信息架构（IA）

把「飞书回归」升级为一个一级主视图 **「回归执行」**（或保留在 应用与环境 下但重构其内部），内部只保留 **2 个区**，取代原来的 4 个 tab：

```
回归执行（某 app 下）
├── 左栏：Runs 列表（合并 执行历史 + Trace列表，二者本是同一批 run）
│     每行：run_id · 用例 · 状态(pass/partial/fail/blocked) · 时间 · 模式(agent/plan)
│     顶部：[▶ 新建执行] 按钮 + case_id 筛选 + 仅pass
└── 右栏：选中 run 的详情（主从）
      ├── 顶部头带：目标/用例名 · 状态 · 设备sn · 指纹 · 模型 · adb/remote通道 · 耗时 · P/F/B/S
      ├── 主体：ExecutionTimeline（实时或回放，同一组件）
      │     每步：#序号 · 缩略图 · 能力(via adb/hitl) · 思考 · 动作(坐标) · 结果 · 耗时
      └── 底部：结束横幅（成功/失败原因）+ [提升为 Baseline] 等操作
```

- **新建执行**：点 [▶ 新建执行] 弹出轻量表单（设备 + 选用例 + 模式auto）→ 启动后**右栏立刻切到该 run 的实时时间线**（从 running 直接看着它跑），左栏该 run 置顶。
- **Baseline**：不再单独 tab，收进 run 详情的操作（"提升为 Baseline"）或用例行的标记。
- **运行状态（图2）**：保持独立（那是设备/服务健康，属另一职责），但在"新建执行"选设备处透出在线状态即可，不混入。

## 4. 核心交互流（一条线）

```
[回归执行页]
  │ 点 ▶ 新建执行 → 选设备(5fda2f6d, adb在线) + 勾用例(app-001) + 模式 auto
  ▼ 启动
[右栏实时时间线]  ← 同页，不跳转
  running: 步骤逐条流入(截图+思考+动作+结果)，顶部头带显示进行中
  遇 ask_human → HITL 弹窗(全局 GlobalHitlDialog，已实现) → 答完继续
  ▼ 结束
[右栏结果]  ← 同一时间线，末尾出结束横幅(失败原因/成功)
  左栏该 run 状态更新为 fail/pass；点左栏任意历史 run → 右栏回放其时间线(同组件)
```

**关键**：实时和历史是同一个右栏、同一个时间线组件。用户"执行完就在原地看结果"，"看历史就在左栏点"，不再有独立 AgentRun 页，也不再有单独的 Trace tab。

## 6. 组件收敛（去重）

| 现状 | 重构后 |
|---|---|
| AgentRun/index.vue（独立页，自带左列） | **删除独立路由**，其时间线抽成 `ExecutionTimeline.vue` |
| 飞书回归 Trace时间轴（另一套时间线） | 复用同一个 `ExecutionTimeline.vue` |
| 执行历史 run 详情抽屉 + Trace列表 | 合并为左栏 Runs 列表 + 右栏详情 |
| 运行 tab（触发表单） | 收进 [▶ 新建执行] 弹窗 |
| Baseline tab | 收进 run 详情操作 |

`ExecutionTimeline` 数据源统一：`{ mode: 'live' | 'replay', runId }`
- live：订阅 WS `agent_step`（已实现）
- replay：`GET /case-runner/agent/steps/{runId}`（已实现）或历史 trace 的 event_results（plan 模式）
→ agent 与 plan 两种执行模式共用一套时间线展示（plan 步骤无缩略图/思考，只显示事件+结果，字段自适应）。
