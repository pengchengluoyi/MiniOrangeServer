## 1. 工具存在的理由

测完以后，每一条结论都能直接当测试结论用：

| 结论 | 测试同学可以做什么 |
|------|---------------------|
| **成立** | 这个风险的这个性质，这版过了 |
| **不成立** | 开缺陷 |
| **未观察** | 还没测到，不能拿它说需求过了 |

没有第四种。**「看起来测了，其实没看见」就是虚假。** 假绿比少测更危险：少测至少知道没测。

通过率只算 `成立 / (成立 + 不成立)`。未观察进「还没测」，不算过，也不算产品失败。

执行器里这两态不要混：

| 状态 | 对应上面哪一格 | 怎么处理 |
|------|-----------------|----------|
| **校验不通过** | 不成立 | 开缺陷；这条立刻停，后面记未观察 |
| **无法验证** | 未观察 | 不算通过，也不开缺陷；不是红，继续下一句 |

两者同时出现时，校验不通过优先。

需求过不过仍是人签。人签的依据必须是这张三态表，而不是「4 条 fail、通过率 0」或时间线 thought。

## 2. 测好、测多、测准

这是测试问题。下发、prompt、时间线都只是为了守住它。

**测好**：观察点对准风险。点问「未购用户首页能看见领取球」，好的观察是这一帧上球在不在；坏的观察是进没进首页（首页几乎总能进，风险没被问到）。「核对页面展示与提示」没有观察点，是空话。桩用例把空话挂到点上，设计已经坏了——执行器再稳，测的也不是那个点。

**测多**：多的是被看见的风险，不是脑图点数、挂载数、冒烟条数。120 个点挂了桩 = 测了 0。提测 4 条跑完，最多看见 4 条路径上的那几句。要增多：能看见的点都看到那一帧；看不了的记未观察，人手补。用更多「进入某某页」把数字做大，是假的多，人会以为点都测过了。

**测准**：成立 = 图上真有这句问的对象；不成立 = 图上真没有。模型空了、没截图、号没登，都是未观察。看见 A 却给 B 点亮（进了首页就当选中态过了）也是不准。

领新人礼 / 新人福利对不上：若预期就是产品应有文案，红是测准；若预期过时、产品已改名，那是观察点写错（测不好）。人要判「缺陷还是用例脏了」，工具不许把其中一种洗成另一种。

## 3. 测试在做什么，校验只咬最下面一层

| 词 | 是什么 | 一条大概长什么样 |
|----|--------|------------------|
| **验收标准 AC** | 需求算不算做完 | 「未购用户能在首页领到新人礼」 |
| **测试点** | 脑图叶子：一类要测的风险 | 「首页展示领取悬浮球」 |
| **用例** | 该点上一种情况的走法 | 前置 + 步骤 + 预期；`正向 / 异常 / 边界` |
| **预期 / 观察** | 某一步做完后，这一帧上成不成立 | 「出现领取弹窗」 |

执行器里的「检查点」是从预期列切出来勾进度的，**不是** 脑图测试点。  
人工验收是整单过不过，不能自动通过。

```
需求 / AC
  └─ 测试点
        ├─ 用例·正向
        ├─ 用例·异常
        └─ 用例·边界
              ├─ 前置（环境）
              ├─ 步骤（去到那个场景）
              └─ 预期（静帧上那句观察）  ← 本工具自动负责的只有这里
人手还要看：动效、换号、Web 改开关、这版能不能过
```

测试点 ≠ 校验。点过了是「这类风险相关的情况都设计到、该跑的跑了」；校验过了是「这一帧上这句成立」。点可以挂了用例但全是无法验证（清单上覆盖了，行为没被证伪）；校验全绿也不说明异常、Web、动效测过了。

同一个点「首页领取球」：

| 情况 | 能不能被本工具观察 |
|------|-------------------|
| 未购，球在 | 能（字/物在不在） |
| 已购，球不在 | 能（不出现） |
| 后台关开关 | 不能（Web 前置） |
| 点击领取出弹窗 | 能 |
| 入场动画 | 不能（无时间轴） |
| 底栏为首页选中 | 看得见但不稳，不当产品红 |

即使用例跑绿，也只覆盖了这个点里 **静帧可见性** 那一条情况，不是整个点。

粗算一条造好物领取/投放类需求（脑图常 80～150 个点）：App 正向且预期能写成字/物/页的大约 25%～40%；去掉桩、写烂的预期、选中态，大约 **15%～25% 的点** 能被引擎认真观察。一个点上正+异+边全被自动看见，大约个位数百分比。提测冒烟只看见冒烟路径上的那几句。

不要用校验通过率当测试点覆盖率，也不要用挂载当自动质量。

## 4. 本工具实际能看见什么

观察发生在 **操作已经结束、新截图、不准再点** 的那一帧上。今天几乎等于单帧看图。dump 有采集，但没接进观察；多帧/声音/设计稿没有。

**能观察（过/不过可以当产品结论）：**

- 文案或物体在不在：「出现领取成功」「不出现领取球」。必须是看得到的字或物。「不出现」= 这张图上没有，不是「可以关掉所以算没有」。
- 到了哪一页：标题、底栏文案、主模块。必须用点完之后的新图。加载中应再等一帧，不要把转圈当「不是首页」。
- 某个控件还在不在：按钮可见、没有登录弹窗。
- 短含义：右下角是领取球、这是商品详情不是直播间。题必须短，不要和选中态捆成一句。

**看得见，但不能当产品红（今天没有稳尺子）：**

- 选中态 / 高亮：压缩、主题、转场帧会漂；dump 也没解析 `selected`。记未观察，不要记不成立。
- 数量 +1：没有操作前快照就是编。图上写着的绝对数可以当文案读。
- 首页上「仍已登录」：首页常常看不出。开场登录闸门是前置，不是这一帧预期。

**不能观察（题要的东西不在这张图里）：** 动画、跟手、声音、震动、好看/符合设计、像素对齐、「功能正常」。不要发看图，记未观察。

一句预期里两句话是两道观察：「进入首页」能看；「底部为选中态」未观察。不要因为后半句 skip 就把前半句也 skip；也不要因为前半句成立就把后半句算过。

观察不准动手。图上有球 = 「不出现球」没过。不准为了凑绿去关球。那是把场景改掉了，测的不是原场景。

## 5. 现在结论为什么不可信

| 发生了什么 | 测试上是什么 | 被写成 |
|------------|--------------|--------|
| 点上只有「打开应用，核对展示」 | 没有观察点 | 覆盖，像测过 |
| 风险是选中/球，只问了进页 | 替身观察 | 成立（假绿） |
| 一句两个性质，只看了好判的一半 | 另一半未观察 | 整句成立 |
| 步骤走完，预期没看就整单通过 | 未观察当过 | 成立 |
| 模型没输出 / 设备没图 | 未观察（工具） | 不成立（假红） |
| 号不对、没登 | 场景没造出来 | 产品没过 |
| 为了让图符合预期去关了控件 | 测的不是原场景 | 成立 |
| 点完立刻用旧图问「进入首页」 | 没看见切完后的页 | 不成立（假红） |

假绿是第一号伤害：验收会过。假红是第二号：缺陷单是脏的，下次谁都不信红。替身观察是第三号：数字好看，风险还在。

领取球提测 `cr-d6f9e9e4cb4a`：001/003 在问选中态——当产品红是假红，因「已经在首页」就当点过了是假绿。014 屏上「领新人礼」、预期「新人福利」——若那句文案是这个点的观察点，红是测准。拆操作/校验 prompt **救不了 014，也救不干净 001/003**；001/003 还要「切页完成后再看」。

最近几天大量时间花在拆 prompt、质检库、意图识别、时间线。那是把执行器做成能自洽讲解的应用。测试要的是上面这张表不再出现假结论，不是事件分得更清。

## 6. 为了结论为真，执行上必须守住的

这些不是产品叙事，是不让结论写假的纪律。

1. **步骤列只负责走到场景，预期列只负责看。** 两列不要拼进同一次看图。混在一起，模型会去关球来让字和图一致。下发时列已经分开，不要再拼回去。操作侧不准出现预期原文；观察侧不准输出坐标、不准点。
2. **看之前必须是操作之后的新图。** 今天 `done` 常把点击丢掉，并用本轮开头那张旧图去验「进入首页」——切页未完成的假红。skip_repeat 同一坐标再点也是立刻验旧屏。
3. **没看见就写未观察，不准写成成立或产品没过。** 选中态、动画、「功能正常」、无快照的 +1、工具空输出、截图失败、号没登：都是未观察（或环境没备好）。有未观察且没有不成立时，整单不是通过。
4. **混合句按句记账。** 「进入首页 + 选中态」必须留下两条：前半成立/不成立，后半未观察。现在只 stamp 前半句，后半句缺口会丢，假绿。
5. **观察点不许改弱。** 宁可将这个点记未观察，不可把「选中态」改成「进了首页」来刷绿。

看图在两类题里都能分析：操作要坐标，观察要「在不在」。缺的不是「看图不会看」，是题出错、图用错、没看见却写了过/不过。

## 7. 接下来只认这五条

做完没有假结论，才是在测。少等、好看、无人值守，都排在这后面。

1. **假绿是否还在**：未观察 → 成立 的通路堵死了没有（桩当覆盖、弱代理进页、混合句只验一半、没看预期却 overall=pass）。
2. **假红是否还在**：工具/环境/旧图 → 产品不成立 的通路堵死了没有（空输出、未切页就验到页、选中态当缺陷、登录闸门误标）。
3. **替身观察是否还在**：看见 A 却给 B 点亮。
4. **能看见的点是否都看见了**：提测可以少跑；功能测试若留下几十条「球在不在」类点没跑，是测得少，不是引擎策略。
5. **测试点表上的三态能不能直接拿去验收和开单**：行是测试点，不是 run。未观察写明原因（没跑 / 场景没有 / 这句看不了 / 人手还没签）。

为这五条服务的实现可以做；再写意图识别、Vision 长文、再画时间线，除非能直接堵住上表里的某一行，否则先停。

用例质量（截断变桩、重试冲掉人改的行）决定观察点是不是空话，仍是测好的前提，见 [plan/plan-qa-role-quality.md](plan/plan-qa-role-quality.md)。那是写点写预期，不是执行策略。

## 附录 · 执行器

已落地：操作/校验两个 prompt；质检库命中才看图；选中态不当产品红；登录前置只有 `session_gate` 真 FAIL 才标准备不足。

**8 月 29 日晚已改（堵假结论）：** `done` 带点会先执行再新图观察；skip_repeat / 进入校验不再用决策旧图；混合句按句 stamp；没看见的预期不再写成过或产品失败；操作目标不再带用例名里的「看不到悬浮球」；首页「保持登录」记未观察。

仍未改、且有争议的见下一节。空输出仍走引擎故障（已是 `execution_error`）。ASSERT_VISION 仍是一套语义尺子。dump 仍不进观察。

验收不要用通过率，用：

1. 操作 messages 里搜不到当前步预期、「不出现 / 选中态」，也搜不到用例名里的「看不到」。
2. 点首页与「观察进入首页」之间至少有一张新截图（或一次 wait）。
3. 预期只有选中态 → 未观察，整单不是产品失败，也不是通过。
4. 「进入首页 + 选中态」必须留下两条结论，不能只因进了首页就整句过。

## 有争议、这轮没擅自改

这些会改变「测什么 / 判多重」，需要你拍板后再动：

| 争议 | 两边 | 现在 |
|------|------|------|
| **产品红之后还跑不停？** | 继续：后面的点也能看见。停：省时间、失败即止。 | **已拍板：红了就停。** 校验不通过停整案；后面记未观察，不当失败。无法验证不是红，继续下一句/下一步。 |
| **混合句前半过、后半看不了，整单算什么？** | 未观察（不能当过）。部分过（前半能引用）。 | **已拍板：整单不算通过。** 没有校验不通过时记 `无法验证`。校验不通过优先。 |
| **文案要不要精确匹配？** | 精确：「领新人礼」≠「新人福利」必红。近义：语义过。 | 仍是一套语义看图，没声明 |
| **dump / selected 要不要这轮接进观察？** | 接了选中态能当真门。不接：继续未观察。 | 先不动 |
| **到页观察前固定等 0.8s？** | 少假红。拖慢每步。 | 到页/文案/控件先等 0.8s 再拍 |
| **功能测试要不要自动跑完所有能观察的点？** | 测得多。提测仍只要冒烟。 | 圈哪些点跑仍是流程圈范围，这轮没改 |
