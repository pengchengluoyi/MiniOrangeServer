# 四类能力：前置 · 步骤 · 预期 · 通用

> 对照：用例三列（前置 / 测试步骤 / 预期）、`plugins/capabilities/`、`roles_catalog.py` 里测试工程师能力、`role_router.py` 的 `case_exec_agent` 剧本。  
> 目的：写用例、看时间线、改执行器时，先问「这是三列里哪一列的，还是不区分列的通用动作」。

---

## 0. 怎么分

执行一条用例只有三列状态。能力按**服务哪一列**归类；点、滑、输入这类动作哪一列都可能调用，单独算第四类。

| 类 | 服务哪一列 | 判据 | 失败算什么 |
|----|------------|------|------------|
| **前置操作** | 前置列 | 开跑前把环境、账号、登录态备好；不验证业务预期 | `PREP.*`；不够则停，做不到则跳过打标签 |
| **操作步骤** | 测试步骤列 | 按编号走到场景；本步内可以自愈 | `STEP.*`；没做成则后面步骤和未验预期全 SKIPPED |
| **预期结果** | 预期列 | 步骤做成之后**只看、不准再点**；同号才验 | `EXPECT.*`；不过才是产品红；看不了是未观察 |
| **通用能力** | 不区分列 | 被上面三类调用的动作/定位/等待/问人 | 记在调用方那一列的结果里，自己不单独出覆盖类 |

禁止：

- 用通用点击去「点掉」预期里的东西来凑绿（观察阶段不准动手）。
- 把看图决策、视觉校验当成同一种能力：前者决定**下一步做什么**，后者判断**这一帧成不成立**。
- 把筛账号、观察登录态写进测试步骤列（那是前置）。

---

## 1. 前置操作

环境能不能开跑。整段先跑完，再进步骤。自愈禁止用在前置。

### 1.1 编排（LLM / 服务，不直接点屏）

| 能力 | id | 做什么 | 何时 |
|------|----|--------|------|
| 筛测试账号 | `pick_account` | 按场景和环境从号池挑号；标签优先，占用中的往后排 | 开跑前，每条用例 |
| 用例场景理解 | `case-scene` | 读用例原文，返回 session_prep / device_need / prep_items。代码钳制枚举。占设备看这趟要操作哪些端 | 申请设备前；登录闸门前 |
| 观察登录态 | `inspect-session` | 看截图判断已登录 / 游客 / 是否微信一键不可测；**只观察，不切号** | 开场；业务用例前置重新登录成功后用 RunContext 跳过 |
| 登录态闸门 | `session_gate`（服务，非 prompt） | 按 CaseScene 的 session_prep 退出再登或不动。登录相关不自动登录 | 业务循环前 |
| 开场是否重开应用 | `agent-restart` | 判断要不要先强关再启动目标包 | 开场 |
| 前置条件解析 | `precondition-parse` | 把飞书「前置条件」拆成 kind + phase | 同步飞书时，不是跑中 |

会话对齐（退出再登录 / 仅退出）会**借用**通用点击、输入，以及看图决策；归属仍是前置，不算测试步骤。登录相关用例不要自动登录，避免把用例自己要测的步骤做掉。

### 1.2 前置库（写在飞书前置列、由 `case_precondition_service` 执行）

| kind | 用例里怎么写 | 落地 |
|------|--------------|------|
| 清缓存 | 无缓存、清缓存、清除应用 | `clear_app_cache`（直清或拟人化走设置） |
| 已装 / 未装微信 | 已装微信、未安装微信 | 查包 |
| 检查 SIM | SIM 卡、手机卡 | Android 可读；iOS → 无法执行 |
| 平台 | iOS 设备 / Android 设备 | 对当前 SN |
| 已登录 / 游客 | 已登录、未登录、游客 | 看图 + 闸门，不对齐不进业务步骤 |
| 客户端版本 | 客户端版本 ≥1.3.0 | `get_app_version`（dumpsys） |
| 已打开 App | 当前已打开某某 App | `get_foreground_app`（dumpsys） |
| 保留权限询问 | 不要预授权、保留权限询问 | 跳过 grant |
| 亮屏解锁、Android grant | 一般不必写 | 预置，开跑必做 |

认得出但做不到（跳过，打无法执行）：Web/运营后台开关、远程配置、造服务端数据、真短信、接电话/推送必达、地理围栏/时间旅行、iOS 读 SIM。

### 1.3 设备能力（主要被前置调用）

| 能力 | id | 说明 |
|------|----|------|
| 唤醒屏幕 | `wake_screen` | 预置 |
| 解除锁屏 | `dismiss_keyguard` | 预置 |
| 清理应用数据 | `clear_app_cache` | 前置 kind=清缓存 |
| 强制结束应用 | `kill_app` | 开场重启 |
| 安装应用包 | `install_apk` | 装包；弹窗许可走拟人化 |
| 读取设备数据 | `read_device_data` | SIM / 型号等，屏幕上看不到 |
| 读取应用版本 | `get_app_version` | dumpsys package 的 versionName；前置「客户端版本 ≥x」 |
| 读取前台应用 | `get_foreground_app` | dumpsys 当前前台包名；前置「当前已打开 App」 |
| 读取设备运行态 | `probe_device_state` | dumpsys 取证 |
| 拟人化清缓存 / 强停 / 允许安装 | `persona-clear-cache` / `persona-force-stop` / `persona-allow-install` / `persona_subtask` | 无特权时走设置 UI |

## 2. 操作步骤

按编号做「人能照着做的操作」。做成之后才有资格验同号预期。自愈只允许发生在本步内（弹窗、点偏重试、短加载）。

### 2.1 编排

| 能力 | id | 做什么 | 何时 |
|------|----|--------|------|
| 看图决策 | `agent-decide` | 看当前截图，每次只决定**下一个动作**（点哪个、滑哪、输入什么、本步是否做完） | 每个测试步骤的闭环里 |
| 单步重规划 | `single-step-replan` | 某步失败或偏离时只重规划这一步 | Plan 路径失败 |
| 纯文本规划事件序列 | `plan-overview` | 不看截图，先排出事件（Plan 模式） | 远程 / 显式 Plan |
| 测试步骤解析 | `case-step-parse` | 飞书「测试步骤」→ 带编号的操作列表 | 同步飞书 |
| Copilot 指令改写 | `copilot-rewrite` | 步骤改写成一条可规划指令 | 旧飞书路径 |

`agent-decide` **主归属是操作步骤**。前置里的会话对齐会复用它，但不把「登录/切号」记成测试步骤成功。

步骤列应出现的动词（命中后才能 `STEP.OK`）：点击、长按、上滑/下滑/左滑/右滑、拖到、输入、返回/Home、打开/关闭/杀进程、等待 N 秒。整句「完成下单并让运营审核」对不上动作表 → `STEP.UNKNOWN`。

### 2.2 做不到的步骤类型（认得出，无法执行）

语音/视频通话、摄像头对特定实物、双指缩放、切到微信/支付宝支付闭环、听声道/震动/闪光、同时操作 Web 后台。

## 3. 预期结果

步骤 n 做成之后，只观察、不准再点。没有编号 n 的预期 → 不验（`EXPECT.SKIPPED.no_expect`），不是无法验证。

### 3.1 编排

| 能力 | id | 做什么 | 何时 |
|------|----|--------|------|
| 视觉校验 | `assert-vision` / `assert_visual` | 看**操作之后的新图**，判断这句预期成不成立 | 同号预期命中质检库之后 |
| Web DOM 校验 | `playwright_check`（服务） | URL / DOM / a11y 能判的文案、到页、登录；能判则不看图 | Web 通道 |
| 质检分类 | `expect_catalog`（服务） | 句子打成文本出现/不出现、到页、数量、含义、无法验证等 | 下发校验前 |
| 目标抽取 | `goal-extract` | 有预期列则当检查点；没有才抽取。禁止把步骤目标当成预期 | 开跑一条用例 |
| 预期效果解析 | `case-expected-parse` | 飞书预期列 → 与步骤编号对齐 | 同步飞书 |
| 断言拆分 | `expectation-claims` | 一条预期拆成可独立校验的 claim | 写时 / 下发前 |

校验与看图决策的差别：决策输出动作（可点）；校验输出成立 / 不成立 / 未观察，**禁止输出坐标**。

### 3.2 质检库（命中后才能当产品结论）

能当产品红/绿：出现/不出现文案或物、进入某页、控件可见、短含义、登录结果（闸门场景）、Web 上 DOM 能看见的同类题。

看得见不当产品红：App 选中态/高亮（dump 未接观察）、无快照的 +1。

不能验（未观察，不开缺陷）：动画/跟手、声音震动、主观观感、连续多帧、像素对齐、「功能正常」。

## 4. 通用能力

不区分前置 / 步骤 / 预期。谁调用，结果就算在谁头上。

### 4.1 手势与输入（步骤最常用；前置会话对齐、拟人化清缓存也会用）

| 能力 | id | 用例里怎么写 |
|------|----|----------------|
| 点击 | `tap_element` | 点击「立即领取」 |
| 长按 | `long_press_element` | 长按 |
| 方向滑动 | `swipe_direction` | 上滑、下滑、左滑、右滑 |
| 拖到 | `swipe_element_to_element` | 拖到（写清起点和终点） |
| 输入 | `input_text` | 输入、填写 |
| 系统键 | `press_key` | 返回、Home |
| 剪贴板 | `set_clipboard` | 少用 |

跟手连续拖、双指捏合：**不是**本类已有能力，不要写成通用动作。

### 4.2 应用与等待

| 能力 | id | 说明 |
|------|----|------|
| 启动应用 | `launch_app` | 前置开场会用；步骤里也可写「打开应用」 |
| 关闭应用 | `close_app` | 步骤或收尾 |
| 等待 | `wait_ms` | 等待 N 秒；三列都可能插入 |
| 等待页面就绪 | `wait_screen_ready` | 切页后再观察；服务步骤后的预期，本身仍是控制动作 |
| 远程脚本 | `exec_script` | 底层通道，不按三列暴露给写作用例 |

### 4.3 看图定位（给动作瞄准，不是校验）

| 能力 | id | 说明 |
|------|----|------|
| 视觉定位 | `locate-vision` | 根据截图给出点击/输入目标坐标。前置拟人化、步骤点击都会用。**不判断预期是否成立。** |

### 4.4 问人（只要填进框的数据）

| 能力 | id | 说明 |
|------|----|------|
| 人工确认 / 输入 / 单选 / 多选 / 传图 / 知会 | `human_confirm` 等 | 号池缺验证码、要选项时。禁止让人去设备上点允许/登录。 |
| 问人话术 | `hitl-composer` | 把卡住的步骤改写成问人的话 |

问人发生在哪一列，缺口就算哪一列（前置缺短信 vs 步骤缺输入）。

## 6. 一条用例里怎么串

```
筛账号 pick_account                    → 前置
用例场景 case-scene                     → 前置（登录闸门 + 设备需求 + 前置 kind）
申请设备 pick_device                    → 前置（读 CaseScene.device_need，按这趟要操作的端占用）
亮屏 / 解锁 /（可选）清缓存 / 开应用     → 前置（调通用动作）
观察登录 inspect-session + 闸门         → 前置
  按 CaseScene.session_prep 退出再登录或只退出；拿不准则 skip
  登录/退出/注册用例 → 不自动登录
  微信一键且无手机号入口 → 不可测，停
for 测试步骤 n:
  看图决策 agent-decide                 → 步骤
  定位 locate-vision + 点击/滑/输入     → 通用，结果记步骤
  本步做成后，若有预期 n:
    质检分类 → 视觉校验 / DOM 校验       → 预期（不准点）
知识沉淀 / 账号打标                     → 跑完，不属于三列
```

---

## 7. 不属于这四类

流程角色（需求分析、脑图、写用例草稿、验收/发版 BM、Wiki）不参与单条用例三列执行。跑完的 `knowledge-capture`、`account-tag` 是收尾，不要塞进前置或预期。

未启用：`call_api`（接口探针）。启用前不要写进预期类。

## 8. 对照设置页

设置 → 扩展包的 Tab 由 `GET /packs/kinds` 下发（`prep` / `step` / `expect` / `generic`），条目见 `GET /packs?kind=`。分类表在 `server/services/packs/exec_classes.py`。写作用例仍用点击、输入、打开应用、出现「某文案」这种说法，不必写内部 id。
