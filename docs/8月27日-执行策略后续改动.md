## 总原则（2–6 共用）

1. **代码管可观测事实，模型管含义。** 能 dumpsys / UI 树 / 截图像素证明的，不要用中文正则或再问一次 VLM。
2. **预防 → 处置 → 决策。** 开跑前把设备调到「可测」；跑中系统层用规则；业务层才看图。
3. **Prompt 只塞索引，正文按需读。** 每步硬塞 3 条全文是现在贵且吵的根因之一。
4. **成功轨迹是提示不是剧本。** 屏幕永远优先；轨迹加速收敛，不代替断言。
5. **账号/登录态是设备上的事实。** 号池 brief 只能当线索，不能当「已经登录」。

下面每条都写：现状问题、目标形态、落地步骤、和现有模块怎么接、风险。

## 2. 预防先于恢复（去掉「正则当大脑」）

### 问题

现在有两处「太傻」的正则，容易混在一起：

| 层 | 文件 | 现在怎么做 |
|----|------|------------|
| 用例前置 | `case_precondition_service._classify_line` | 用「清缓存 / SIM / 已登录」等关键词把中文行分类 |
| 业务护栏 | `agent_executor._env_manufacture_reason` | 用「退出登录 / 清数据 / 空 feed」禁止凑环境 |
| L0 恢复 | `plugins/recovery/*.yaml` | 已经是证据字段 + 规则，方向对；但 `mode=advise` **没有消费者**，权限框仍靠业务 Agent 自己点 |

前置分类用正则可以接受（输入就是人写的中文栏），但 **「已登录」不该用正则当检查，也不该在 CaseRunner 里直接跳过**。恢复层不该再靠业务 prompt 里的中文铁律去点系统框。

### 目标

开跑前做 **设备预置（deterministic）**，跑中系统框走 **L0 规则（YAML，可带一次小模型）**，业务 Agent 不再负责亮屏/权限/杀错包。

```
开跑一条用例
  1. 解析前置 → 结构化意图（可仍用规则，但输出是 enum，不是「再拿原文去匹配」）
  2. Provision（预防）
       亮屏、解锁、目标包可启动、声明式授权（能 grant 的权限直接 pm grant）
  3. 按意图做环境
       clear_cache → pm clear
       need_logged_in / need_guest → 见第 6 条（设备事实），这里只提出需求
  4. Agent 循环
       预筛停滞/黑屏 → L0 规则
       权限框 YAML 从 advise 改成：能点的确定性点击 + 点不了再 SystemAgent 看图（有界 2 步）
```

### 落地（建议分两期）

**P0 预防清单**（新模块 `server/services/runtime/device_provision.py`）

每条用例、在 `run_preconditions` 之前或之内，固定做：

1. `wake_screen` + `dismiss_keyguard`（已有 capability，直接 dispatch，不经过业务 decide）
2. 目标包 `am start` 失败才记 warning，不在这里清数据（清数据仍看前置意图）
3. Android：对应用声明的 runtime permission 做 `pm grant`（从 APK/`dumpsys package` 读 requested，白名单：相机/存储/位置等；**不** grant 通知监听、辅助功能）
4. 输出一份 `provision_report` 挂到 trace：`awake/unlocked/granted[]/skipped[]`

这一步替代「过夜息屏靠 L0 开场查一次」的大部分情况。L0 仍保留作漏网。

**P1 前置意图结构化**

`_classify_line` 的输出从「kind 字符串」升为：

```json
{
  "intent": "clear_app_data | require_sim | require_wechat | require_platform | require_session",
  "session": "logged_in | guest | any",
  "raw": "原文",
  "confidence": "rule | llm"
}
```

- 规则能认的仍用规则（便宜、稳定）。
- **认不出的行**不再 `unknown` 直接 skip：用一次小模型抽意图（job=`precondition-parse`），抽失败才 skip。
- `require_session` **必须进入第 6 条**，CaseRunner 不得再假装没看见。

**P1 L0 advise 接上消费者**

`system_permission_dialog.yaml` 现在 `mode=advise` 且 Agent 不读 `prompt_snippet`。改成：

1. 命中权限框 → 先尝试 YAML `actions`（点「仅在使用中允许」用 hierarchy `text` 锚点，不要像素）
2. 失败 → 临时把 `prompt_snippet` 注入 **下一次** `decide_next_action` 的 system 旁路块（最多 1 步），或单独 `system-decide` job（预算 2）
3. 禁止点「拒绝」写在代码里：hierarchy 命中拒绝文案的节点直接过滤

业务 prompt 里那些「遇到弹窗自己点」可以留作兜底，但 **系统权限不应再占用业务决策预算**。

### 架构提升

- 业务 Agent 的菜单变干净（`wake_screen` / `probe_device_state` 继续 `visible_to: system`）。
- 前置从「字符串碰运气」变成「意图 → 动作」，第 6 条才接得上。
- 正则仍可存在于 **分类器**，不再存在于 **处置器**。

### 待确认

- `pm grant` 是否允许在测试机上默认全开？部分用例要测「拒绝权限后的降级」，需要前置写 `keep_permission_prompt`。
- SystemAgent 独立 LLM vs 给业务 decide 塞一段 snippet：建议独立 job，避免污染目标。

## 3. 断言分级：像素 diff / 节点存在 vs VLM 含义

### 问题

现在几乎所有「成没成」都是 `assert_visual`（VLM 看图）。过程检查点、终态、假 done 回灌，全挤在同一种工具上。VLM 擅长「这是不是登录成功」，不擅长「底栏四个 tab 还在不在」「标题字号有没有偏」。

### 目标：三层断言，按检查点 kind 选工具

| 级别 | 名字 | 何时用 | 怎么判 | 谁执行 |
|------|------|--------|--------|--------|
| L0 | `node_exists` | 控件/文案「在不在」 | UI dump 或 OCR：text / resource-id / content-desc 命中 | 代码，0 LLM |
| L1 | `visual_diff` | 布局/样式/错位 | 与 baseline 截图比（可设 ignore 区：时间、头像、数字） | 代码 + 阈值 |
| L2 | `meaning` | 业务含义（已发布、空态对象对不对） | 现有 `assert_visual` | VLM |

检查点在 `extract_goal` 时就要带 `assert_level`（规则可先猜，人可在用例上改）：

- 原文含「出现 / 展示 / 可见 / 按钮」→ L0
- 原文含「样式 / 对齐 / 与设计稿」→ L1（无 baseline 则降级 L2 并打标 `assert_degraded`）
- 原文含「成功 / 失败提示含义 / 数量+1」→ L2，且数量+1 **必须**有 `remember` 里的操作前快照

`status=done` 时：

1. 所有未完成的 **terminal** 检查点按级别跑一遍（短路：L0 失败不必再烧 L2）。
2. L2 仍最多假 done 2 次。
3. 任务统计：`partial`（预算耗尽）不要再打进 `failed` 计数——单独字段或 status=`partial` 计入 `blocked`/`declined` 之外的第四类。这是统计 bug，可随断言改一并修。

### 落地

**P0**

- `schemas.CaseCheckpoint` 增加 `assert_level: node | diff | meaning`（默认 `meaning` 以保持兼容）。
- 新 executor 能力或 internal 函数：
  - `assert_node`：params `{text?, resource_id?, contains?}` + 当前 dump/OCR
  - `assert_diff`：params `{baseline_shot, ignore_rects[], max_delta}`
- Agent 在 `done` 时不要只调 `_assert_goal`；按检查点列表分发。

**P1**

- 成功用例把「终态截图 + dump 签名」写入 trace，供 L1 baseline。
- 动态区：数字、相对时间，用 dump 文本比图更稳；diff 默认忽略状态栏。

### 架构提升

- 决策 VLM 与判定 VLM 职责分开：decide 只管「下一步点哪」，pass/fail 尽量可复现。
- 为第 5 条轨迹回灌提供「可脚本化的断言」：节点级检查点可以直接变成回放脚本的 assert，不必再请模型。

### 待确认

- L1 用整图 SSIM 还是区域模板？建议先 **区域**（检查点描述里的控件 bbox，来自 dump）。
- iOS 无 dump 时 L0 只能 OCR，要接受误检。

## 4. 知识：索引 + 按需展开 + 冲突优先级

### 问题

每步 `match_testing_knowledge` top-3 **全文**塞进 prompt。冷启动空、热启动吵、两条知识打架无裁决。路径 nudge 只是再决一次，治标。

Playbook 已退出每步 prompt，检索没命中 = 没说明书。

### 目标（对齐 OpenClaw skill 索引，而不是每步 RAG 填鸭）

```
知识库
  → 编译成 Index（每条 ≤ 200 字：id, title, when, scope, precedence）
  → 每步只把 Index 里「可能相关」的 8～12 条标题+when 给模型
  → 模型若要用，输出 knowledge_ids: ["k_12"]
  → 代码再读正文塞进下一步（或本步重决一次，限 1 次）
```

冲突优先级（高者胜，同名/同 when 只留一条）：

1. `case` 本条用例人工钉住的知识  
2. `app` 已审核的应用知识（含说明书拆条）  
3. `system` 跨 app（权限框、息屏）  
4. `learned` 跑后草稿且未审 → **禁止进 Index**

`when` 用结构化标签，少用自由文本：`page=login` `intent=enter_tab` `session=guest`。检索先过滤标签，再打分。

### 落地

**P0**

- `system_settings_service` 增加 `knowledge_index_brief(app_id)`：只返回已审核、`used=true` 的 `{id,title,when,scope}`。
- `decide_next_action` 的 user 模板：把「本步相关知识全文」换成「知识索引」；允许模型输出 `knowledge_ids`。
- `AgentExecutor`：若 `knowledge_ids` 非空，拉正文，**仅下一循环**带 `knowledge_body`（限 1 条或合计 800 字）。禁止本步已经 decide 完再改动作（除非 parse 后发现 ids 且尚未 dispatch——可本步重决 1 次）。

**P1**

- 开场把 playbook 拆成 Index 条目（登录怎么走、底栏有哪些），`scope=app`，不必每步塞整本说明书。
- 审核流保持：捕获仍产草稿；Index 编译只含已审。

### 架构提升

- Token 从「每步 3 篇作文」变成「目录 + 偶尔一篇」。
- 知识从「检索系统替模型选」变成「模型声明引用」，可审计（时间线已有 `knowledge` 字段，改为展示 *index hit / expanded id*）。
- 和第 2 条 L0 知识分家：系统条目 `scope=system` 只给恢复/预置看，不进业务 Index。

### 待确认

- 模型不填 `knowledge_ids` 时，要不要强制展开最高分 1 条？建议 **不要**，否则又变回硬塞。路径类知识可在 Index 的 `when` 写清楚，靠模型自己点名。

## 5. 成功轨迹回灌（不是旧 Plan baseline 的复刻）

### 和旧 baseline 的关系

| | 旧 Plan baseline | 本方案轨迹 |
|--|-------------------|------------|
| 存什么 | 整段 `events[]` 当剧本 | 成功动作摘要：能力 + 语义目标 + 可选节点锚点 |
| 怎么用 | `generate_overview` 当结构参考 | 给 Agent 当 **few-shot 提示**，可推翻 |
| 坐标 | 经常是像素 | **尽量升级成 text/resource-id**；像素只作 hint |
| 失败 | replan 拼队列 | 不回放失败步；从最近一个仍成立的检查点续 |

现在 `agent_memory.save_trajectory` 已经在 PASS 时落盘，**明确不进 decide**。旧 `m_case_baseline` 仍给已停用的 Plan 用。

### 目标

PASS 后写两种资产：

1. **Hint 轨迹**（给模型）  
   `tap 文案=发布` → `wait` → `assert_node 发布成功`  
   12 步以内，进 prompt 一块「上次成功怎么走（可推翻）」。
2. **锚点脚本**（给代码，可选）  
   连续 ≥2 次 PASS 且节点锚点稳定 → 允许 `replay_mode=script_then_agent`：先按锚点走，走偏（节点找不到或 diff 过大）立刻 **交回 Agent**，不把脚本失败当产品失败。

第一次跑仍探索；第二次起少付探索税。这不是把 Agent 变回 Plan。

### 落地

**P0（只做 Hint，最小）**

- `run_agent_case` 里 `load_trajectory` + `trajectory_to_hint` 已存在，接入 `decide_next_action` 的 `memory_block` 或独立 `traj_block`。
- 存盘时把 `params.x/y` 尽量换成当时 dump 命中的 `text/resource_id`（`hierarchy.resolve_target` 反查最近节点）。下次提示写 `tap text=同意` 而不是 `@612,1840`。
- 设备指纹仍作 key；找不到则退回任意设备的同 case 轨迹，prompt 标明「来自其他机型，仅供参考」。

**P1（脚本化 +  humangate）**

- 轨迹 `blessed=auto|manual`。auto 仅 hint；人工 promote 才允许 script_then_agent。
- 与第 3 条：脚本步的断言用 L0/L1，不用 VLM。

### 架构提升

- 终于用上 `m_case_run_trace` 这座金矿，而不是每条用例从零探索。
- 和 Plan baseline 分家：Agent 不恢复 `generate_overview`。
- 失败回放仍看 thought；成功路径可复用、可审计。

### 待确认

- 是否默认打开 Hint？建议 **PASS 轨迹默认注入 Hint**（短、可推翻），script 模式默认关。
- 应用改版后旧轨迹会害人：加 `app_version` / playbook `version`，对不上则不注入。

## 6. 环境做成设备事实（号池 ≠ 登录态）

### 问题

`bind_account_for_case` 只把手机号写进 `accounts_brief`。不登录、不锁号、不验当前是谁。CaseRunner 又跳过 `after_launch` 的「已登录/游客」。Agent 只能靠看图猜，首页看不出登录还被 prompt 说成正常。

### 目标

开跑前给出 **SessionFact**，写进 RunContext，后续决策/断言/号池打标都认它：

```json
{
  "required": "logged_in | guest | any",
  "observed": "logged_in | guest | unknown",
  "identity": "phone=138**** | guest | unknown",
  "account_id": "env 号池 id 或空",
  "how": "node_tabs | dump_prefs | login_flow | skipped"
}
```

规则：

- 前置 `require_session=logged_in` 且 `observed!=logged_in` → **先登录，再进业务循环**（登录是子流程，预算单独，例如 8 步），失败则本条 `goal_unreachable`，不要在业务目标里顺便登录。
- 前置 `guest` 且已登录 → **不要业务里点退出**（除非用例就是测退出）。优先换号/清数据/换设备；清数据必须前置允许。
- 号池号码与 `identity` 不一致 → 视为环境错误，不要继续点业务。

登录子流程允许：`input_text` 号池手机号、验证码（备注固定码或 HITL 只要码）、点同意。禁止请人去设备上点。

### 落地

**P0 观察（只读，先不自动登录）**

- 开场重启后、第一次业务 decide 前：强制 `inspect_session`（不要等「点过页面」）。判断顺序：
  1. playbook 底栏 tab 是否齐全（已有 `_main_tab_bar_logged_in`）
  2. 是否登录页 marker
  3. 必要时再 VLM（现有 `inspect_session`）
- 把结果写入 `ctx.session_fact` 和 Agent `_session_note`。
- 前置要求已登录但 observed=guest → 本条直接 fail，summary 写清「需要已登录，当前是登录页」。先做到 **诚实**，再做自动登录。

**P1 自动对齐**

- `session_align_service.ensure_session(required, account)`：
  - logged_in + 号池有号 → 走登录子 Agent（菜单子集：tap/input/wait/human_input_text）
  - guest + 已登录 + 前置允许清缓存 → `pm clear` 再启动
  - 否则 fail
- 登录成功后再跑一次 inspect，写入 identity，供第 5 条轨迹和第 4 条知识的 `when=session`。

### 架构提升

- 登录从「业务目标的噪音」变成 **环境闸门**，和清缓存同级。
- 号池从 prompt 文案变成 `account_id` 绑定；`account_tag_service` 可以按真实 observed 打标，而不是按用例文本猜。
- 与第 2 条预置衔接：先亮屏授权，再对齐会话，再 Agent。

### 待确认

- 微信一键登录无法纯自动化：P0 就 fail 并 `needs_human` 要验证码/选择登录方式，还是标 `untestable`？建议 **untestable + 知识草稿「如何登录」**，不要让 Agent 在登录页耗尽预算。

## 对现有架构的叠加关系

```
CaseRunner 任务壳（已有）
  device_provision     ← 新增，第 2 条
  session_align        ← 新增，第 6 条
  AgentExecutor        ← 已统一，第 1 条
      L0 recovery YAML ← 第 2 条接上 advise
      knowledge index  ← 第 4 条
      traj hint        ← 第 5 条
      assert L0/L1/L2  ← 第 3 条
  CapabilityRouter + executors（不动）
```

不改 Router/Executor 合同，只改 **开跑前后的事实层** 和 **Agent 的观察/判定输入**。这是和「再写一堆 prompt 铁律」的本质区别。

3. 第 5 条 P0（轨迹 Hint）——立刻减少第二跑探索税  
4. 第 4 条 P0（索引）——降本、降吵

## 拍板落地备注（2026-08-28）

- **Android grant**：白名单相机/麦克风/位置/存储/通知/通讯录/电话状态；不 grant 通知监听、辅助功能、悬浮窗、WRITE_SETTINGS、用量统计。无 adb serial（纯 Claw）则跳过 grant 并记 `no_adb_serial`。
- **iOS**：明确 `ios_no_tcc_grant`。默认 `_accept_ios_alert`（WDA）；`keep_permission_prompt` 时连 Alert 也不点。L0 `system_permission*` 在保留询问时跳过。
- **保留询问**：前置写「保留权限询问 / keep_permission_prompt / 不要预授权 / 拒绝权限」。仅「弹出权限后点击允许」不算 opt-out，仍默认 grant。
- **知识**：`match_testing_knowledge` 只取 **approved**；登录学习 `source=login_learn` 且 **禁止自动审核**，必须人审才进 Index。
- **untestable**：任务计数单独字段，**不进 failed**，通过率分母不含它。
- **Copilot**：`run_cases(instruction=)` 合成临时用例 `chat-*`，无登录前置 → 闸门 `any`。Slash 与 `navigate` 仍本地。
- **轨迹 Hint**：`save_trajectory` 仍不进 decide，本轮不接。
