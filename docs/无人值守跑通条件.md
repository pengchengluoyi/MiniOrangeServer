# 何时可以不需要人工介入、自己跑完一轮

> 写于 2026-08-28。对照源码：[plan/backend-execution.md](plan/backend-execution.md)，对照拍板：[8月27日-执行策略后续改动.md](8月27日-执行策略后续改动.md)。  
> 样本：本机 `m_case_run_trace` 最近 **200** 条（截至当天 12:40）。这是本机真实跑次，不是全量线上。

---

## 0. 先说结论

**现在还不能把一轮用例丢下就走。**

最近 200 条里：`pass` 42、`fail` 128、`partial` 8、`blocked` 7。通过率大约 **两成**。人真正被 HITL 弹窗堵住的已经很少；把人拖回来的是三类「意外」：

| 意外 | 最近 200 条大约 | 人要做什么 |
|------|-----------------|------------|
| 模型空输出 / JSON 解析失败，整条 `give_up` | **53** | 重跑或换 Key |
| 同一入口连点，旧逻辑判「卡死/震荡」或一直看图 | **23** + 今天 `cr-c5d4db9be81d` 人取消 | 取消任务、改判定 |
| 设备通道（iOS DDI/WDA、息屏、截图失败） | 若干，iOS 更重 | 插线、开 Xcode、亮屏 |

「不需要人工介入」**不是**「全绿」。产品上应定义为：

1. 开跑后 **不碰手机、不点系统允许、不回 HITL、不取消任务**。
2. 批次里每条用例自己走到终态：`pass` / `fail` / `untestable` / `partial`，**没有 `running` 挂死、没有一直看图**。
3. 失败可以归到稳定分类（环境 / 不可测 / 真缺陷 / 引擎故障），**不要靠人从时间线猜「它卡在哪」**。

下面按「现在为什么不行 → 什么时候才算行」写。闸门是 **AND**：缺一条就不能宣称无人值守。

---

## 1. 一轮实际在跑什么

测试页 / 需求准入 / 飞书批次 / 对话小窗，最终都是 `CaseRunner.run_cases` → `AgentExecutor` 看图闭环。每条用例开跑前大约是：

```
亮屏解锁 + Android pm grant（预置）
  → before_launch 前置（清缓存 / SIM 等）
  → 号池只写 accounts_brief（不登录、不锁号）
  → 开场是否杀进程重进
  → 登录态闸门（前置写了已登录/游客才查；不对齐直接 fail / 微信-only untestable）
  → 看图 decide → 点/滑/输入/断言 → 直到 done 或预算耗尽
```

对话小窗合成的 `chat-*` **没有登录前置**，闸门是 `any`，不挡登录。需求准入用例通常写「已登录」，闸门会挡。

拍板里和无人值守直接相关、**本轮没做**的：

| 项 | 现状 | 对无人值守的影响 |
|----|------|------------------|
| 自动登录 | 只观察，不对齐就 fail | 设备没挂对号 → 整条红，要人先登 |
| 成功轨迹 Hint | `save_trajectory` 不进 decide | 每条从零探索，步数和看图都贵 |
| 断言分级 L0/L1/L2 | 几乎全是 VLM `assert_visual` | 「底栏是否选中」这种题会看图打转 |
| L0 `mode=advise` 权限框 | 只记不处置 | grant 漏网时仍可能等人点允许 |

## 2. 人现在还会被拖进来的原因

分成 **跑前必须人准备**、**跑中会喊人**、**跑中其实不喊人但人不得不盯** 三类。无人值守要消灭的是后两类；第一类允许在开跑前做一次，跑起来就不要再要人。

### 2.1 跑前：环境一次性准备（允许，但不算「跑中介入」）

这些现在 **代码不会替你做完**，开跑前必须成立，否则一轮里会大面积红或直接不可跑：

| 条件 | 现在谁负责 | 不成立时发生什么 |
|------|-----------|------------------|
| Android 机亮着、adb 能控、目标包已装 | 预置会 wake + unlock；装包不会 | 截图失败 / 启动失败 |
| iOS DDI + WDA 就绪 | **没有**自动挂载 | 截图失败、模型 give_up「需要人去开 Xcode」 |
| 应用已登录到用例要的身份 | 闸门只检查，**不登录** | `goal_unreachable`：需要已登录，当前是登录页 |
| 号池有手机号；验证码若是短信 | 备注里有固定码才自动填 | 没有固定码 → `ask_human` 等短信，超时 `needs_human` |
| 微信一键登录 | 标 `untestable` | 不红，但本条等于没跑 |
| 用例要「拒绝权限 / 保留询问」 | 预置跳过 grant | 框弹出来要 Agent 自己点；点不好就卡住 |
| 信息流里要有视频/指定内容 | 号池标签很弱 | 滑很久 give_up「feed 里没有」 |

**开跑前人可以做、跑中不要再做：** 装包、登录一批号、WDA 保活、确认机架供电。这些准备好，才谈无人值守。

### 2.2 跑中：还会喊人（HITL / 等人点设备）

代码已经把 HITL **收窄** 成「只要填进输入框的数据」，禁止「请你去手机上点允许/登录」。号池已有手机号或固定验证码会短路弹窗。

因此跑中喊人，现在主要只剩：

1. **真短信验证码**（号池备注没写死码）。
2. **模型仍 `ask_human` 要一个号池没有的字段**，超时（默认几十秒到数分钟）→ `blocked` / `needs_human`。
3. **系统权限框 grant 漏了**，且 L0 advise 规则没有消费者：业务 Agent 可能点，也可能一直看图。`system_permission_dialog.yaml` 仍是 `mode=advise`。
4. **iOS 没有 `pm grant`**，只能尝试关 WDA Alert；关不掉就要人在设备上点。

最近 200 条里带「需要人工 / HITL」字样的大约十几条，且多半是 **8 月 17 日前后的 iOS WDA/DDI**，不是今天 Android 回归的主因。今天把人叫回来的，更多是第 2.3 节。

### 2.3 跑中：不弹窗，但人不得不盯（这是当前主问题）

这些 **不会** 出 HITL，但任务停不下来或结果不可信，人只能取消或死等：

| 现象 | 机制 | 今天的例子 |
|------|------|----------------|
| 一直截图 + VLM | 同一入口再点；旧震荡检测改成只劝不打断之后，会看到任务取消才停 | `cr-c5d4db9be81d` 点「首页」屏幕不变 |
| 执行超时 | 单用例墙钟 20 分钟仍未完成 → `partial` | 原先用 `max_steps` 15～20 卡死，例如 `cr-b72e0c8a5ea4` |
| 模型空白 | `decide_next_action` 解析失败 → `give_up` + `llm failed` | 200 条里 53 条，最大头 |
| 假卡死 | 已在目标静态页，再点当前 tab 不会切页，却报「卡死/震荡」 | 改检测之前的 VIEW-007 / 首页 tab |
| 过程检查点当终态 | 「底部首页为选中态」用 VLM 看，看错了就去点首页 | 和上一条叠在一起 |

8 月 28 日已改：**同一落点再点不再检测页面有没有切换**，跳过这次点击，改做后续检查点/成功标准（例如去看领取悬浮球）。这能去掉「为人取消而存在的看图循环」，**不能**保证后续目标在屏上。`cr-b72e0c8a5ea4` 在改动之后仍因步数上限停跑，说明卡点从「切没切页」变成了「悬浮球在不在 / 账号是不是对的」。主循环现已改为墙钟 20 分钟，不再用 `max_steps` 卡死。

## 3. 「意外」按层拆开（不是一个大锅）

无人值守要分别关掉这些意外。混在一起会永远觉得「Agent 不稳」。

### A. 引擎故障（不该算产品失败）

| 意外 | 现在归类 | 应该变成 |
|------|----------|----------|
| LLM 空 / 熔断 / 截断 | 整条 `fail` + `execution_error`（thought 常是「LLM 返回空/解析失败」） | 本步重试或换备用 Key；仍失败记 **引擎故障**，不要写成用例没过 |
| 截图失败（adb/WDA） | `execution_error` | 通道健康检查，批次跳过该设备或标 `device_unhealthy` |
| 空白熔断过严 / 过松 | 有流式早停，仍有 53 条空输出 | 统计 `fail_kind=melt\|parse`，按模型设阈值 |

**没有把 LLM 空输出从「用例失败」里拆出去之前，不能说无人值守。** 它是样本里最大的随机红。

### B. 环境闸门（应该红，但必须开跑前可预防）

| 意外 | 现在 | 无人值守要求 |
|------|------|----------------|
| 要已登录，设备在登录页 | P0 **直接 fail**，学登录草稿（pending） | 要么人先登好，要么做完 **自动登录子流程** 再进业务 |
| 要游客，当前已登录 | fail，禁止业务里点退出 | 开跑前清数据/换号，或前置允许 clear |
| 微信-only 登录 | `untestable`，不进 failed | 批次里这类应预先剔除或单独队列 |
| 无 SIM / 要微信已装 | `before_launch` 前置 | 设备标签不匹配就不要派到这台 |

这类红 **可以接受** 出现在报告里，前提是：同一台设备、同一个号，下一轮不再重复踩。现在 **不会自动对齐会话**，所以「已登录」用例在冷设备上会稳定红——这是诚实，不是意外；但值班的人仍要先登号，算人工介入。

### C. 导航与判定（产品看起来像「Agent 傻」）

| 意外 | 根因 | 收敛方向 |
|------|------|----------|
| 连点首页 / 当前 tab | 用「页面是否切换」当成功；静态页不会切 | 已改为跳过连点、做后续（待用同一条用例回归验证） |
| 「选中态 / 已进入」当检查点 | 全走 VLM | 拍板第 3 条：节点存在走 dump/OCR，不要看图 |
| 成功标准含糊 | `assert_visual` 对整张图讲中文 | 终态可观察、可 L0；数量变化必须有 remember |
| 知识不点名就不展开 | 模型经常不填 `knowledge_ids` | 路径类 Index 的 `when` 写清楚；仍不要硬塞正文 |
| 每条从零探索 | 轨迹不进 decide | Hint 回灌（拍板第 5 条，未动） |

### D. 应用与账号内容（有时是真缺陷，有时是环境）

模型 give_up 的原文里已经出现：feed 没有视频、没有旧新人礼对话、风格缩略图一直占位、关注弹出登录。无人值守要求 **号池标签 + SessionFact** 能在开跑前说清「这号有没有新人礼 / 是不是空 feed」。现在 `bind_account_for_case` 只选号、不验设备上是谁。

## 4. 什么时候才可以宣称「自己能跑完一轮」

分三档。不要用「再优化 prompt」当作档位。

### 档 0 — 值班可以去倒杯水（任务会自己停）

**目标：** 人不取消，任务也不会一直看图。失败可以第二天再看报告。

必须同时满足：

- [x] 统一 Agent，不再 Plan/Agent 分叉
- [x] 截图失败有上限（连续 2 次停）
- [x] 决策步 / 连续 wait / 假 done 有上限
- [x] HITL 不能改成「请人点设备」
- [ ] **同一入口连点不会无限看图**（代码已改，需用 `case-nr-app-001-ok` 复跑确认：应出现 `skip_repeat_tap` 并去做悬浮球，而不是人取消）
- [ ] LLM 空输出 **不** 无声杀条；至少重试 1 次或标引擎故障后继续下一条（批次已经会继续，但单条仍像产品红）
- [ ] 批次结束时没有 `overall_status=running` 的僵尸 trace

**现在：接近档 0，但还没验收。** 连点问题刚改；LLM 空仍是最大随机红。

### 档 1 — 过夜 Android 回归（真无人值守的最小集）

**范围先收死：** 只跑 Android + USB/adb、前置「已登录」、**不要**微信登录、**不要**真短信、**不要**「拒绝权限」、feed 内容不依赖当天推荐。

必须再满足：

| # | 闸门 | 验收怎么量 |
|----|------|------------|
| 1 | 设备预置后，开场不再靠人亮屏；权限框 grant 白名单命中，漏网框 L0 **deterministic 点允许**（advise 要有消费者） | 连续 20 条开场 `recovery` 不是人点的 |
| 2 | 机架上的号 **已经是** 用例要的登录态；闸门通过率高，fail 只来自真的掉登录 | 同机同号连跑 2 轮，登录闸门 fail ≈ 0 |
| 3 | 连点 / 静态 tab 不再出现「人取消」或旧「卡死」文案 | 新人礼首页用例 3 次：要么验到悬浮球，要么 `goal_unreachable` 写清「屏上没有」，不要 `cancelled` |
| 4 | LLM 空/解析失败 < **5%** 步，且不计入用例失败分子（或自动换备用 provider 再 decide 一次） | 调度日志 `agent-decide` 的 `fail_kind` |
| 5 | 一轮全部终态；墙钟可接受（单条分钟级，不要 18 分钟空转） | 任务 `status=done`，无手动取消 |
| 6 | 通过率解释得清：红的是环境 / 不可测 / 断言没看到，而不是引擎 | 报告里 `failure_category` 与摘要一致 |

档 1 **仍然要求人在开跑前登录好账号**。这是「跑中无人」，不是「从刷机到出报告零人」。

### 档 2 — 冷设备也能自己跑完（少一次登号）

在档 1 之上：

| # | 闸门 | 说明 |
|----|------|------|
| 7 | **自动登录子流程**（拍板第 6 条 P1）：号池手机号 + 固定验证码走完登录，再 `inspect_session` | 没有固定码的号不要派给无人批次 |
| 8 | 游客用例：前置允许时 `pm clear`，不允许就换设备/换号，禁止业务里点退出 | 已有护栏，缺的是对齐动作 |
| 9 | 成功轨迹 Hint 进 decide（可推翻） | 第二跑探索税下降，减少空转直到超时 |
| 10 | 检查点分级：选中/可见 → 节点断言；含义 → VLM | 「首页选中」不再烧一轮看图 |
| 11 | iOS：DDI/WDA 健康检查，不健康 **不要派用例**，不要让模型写「请去开 Xcode」 | 派工前 `device_unhealthy` |

档 2 之后，才适合把「需求准入一整包」丢给夜间任务。微信登录、真短信、要测拒绝权限的用例，**永远**不要进这个队列，继续 `untestable` 或单独人工场次。

## 5. 建议的验收包（不要用「感觉稳了」）

用固定小包，而不是每次换用例。

**包 A（档 0 / 连点）：** `case-nr-app-001-ok`（首页领取悬浮球），设备已登录、adb 在。  
期望：不再手动取消；时间线有「入口已点过 / skip_repeat_tap」或直接去断言悬浮球；有球 `pass`，没有球 `fail` 且摘要写「屏上未见」，不要 `cancelled`。

**包 B（档 1 过夜）：** 10 条「已登录 + 无微信 + 无短信」Android 用例，同一台机连跑 2 轮。  
期望：无 HITL、无取消；登录闸门第二轮 fail=0；LLM 空 <5%；`partial` 要能指出缺哪步。

**包 C（档 2 冷启动）：** 对包 B 的机先登出或 `pm clear`（仅当用例允许），看自动登录是否把闸门做绿，再跑业务。

过不了包 A，不要谈无人值守。

## 6. 为无人值守排期（只排会减少「人盯 / 意外」的项）

和 8 月 27 日开工顺序不同：那里是功能拍板。这里只为 **人可以离开**。

| 顺序 | 做什么 | 关掉哪种意外 |
|------|--------|----------------|
| 1 | 复跑包 A，确认连点不再取消任务 | 人盯时间线 |
| 2 | LLM 空：decide 失败重试 / 备用 Key；空输出不写成业务 give_up | 最大随机红 |
| 3 | 权限框 advise 接上点击（YAML actions 或有界 system-decide） | 漏网权限等人 |
| 4 | 过夜批次只派「已登录已对齐」的 Android | 档 1 |
| 5 | 自动登录 + 固定验证码（无码的号剔除） | 冷设备 |
| 6 | 轨迹 Hint | 空转直到超时 |
| 7 | 节点断言（选中/可见） | VLM 打转 |
| 8 | iOS 健康检查后再派工 | DDI 把人叫回来 |

不要做的（对无人值守没帮助，还增加意外）：

- 让 Agent 在业务目标里顺便登录、顺便点微信。
- 把短信 HITL 当默认登录。
- 默认打开脚本回放（拍板已冻结）。
- 用「再写一段 prompt 铁律」代替闸门和断言分级。

## 7. 一句话对照

| 问 | 答 |
|----|----|
| 现在能不能丢下一轮就走？ | **不能。** LLM 空输出和「找不到目标仍看图到预算/取消」还在。 |
| 人最少要做什么？ | 开跑前：机亮着、adb/WDA 好、**号已登录**、包里没有微信/真短信。跑中尽量不要碰。 |
| 什么时候可以过夜？ | 档 1 清单全勾，并且包 B 过。 |
| 什么时候可以冷设备也过夜？ | 档 2：自动登录 + Hint + 节点断言 + iOS 不派病机。 |
| 哪些用例永远不要进无人队列？ | 微信一键登录、真短信、测拒绝权限、依赖「今天 feed 里刚好有某条内容」且号池保证不了。 |

代码已经把「执行引擎」收成一条 Agent，并把登录失败从装看不见改成了直接 fail。剩下的不是再做一个引擎，而是：**让失败可预期，让循环必终止，让登录/权限/断言不要靠人在屏幕前补刀。**
